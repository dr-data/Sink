## 2024-05-12 - Avoid Inline Write Migrations & N+1 Queries in Serverless Cloudflare KV
**Learning:** Performing inline database write operations (like `KV.put`) within read loops (e.g. while fetching lists of links) severely degrades performance and explodes write operations count (resulting in 66.62k+ ops) in a NuxtHub/Cloudflare KV environment. Additionally, retrieving metadata for individual keys sequentially using `KV.getWithMetadata()` results in a devastating N+1 query pattern.
**Action:** Always utilize the `metadata` returned directly inside the keys array from `KV.list()`. If metadata migration is needed, do NOT execute it inline during read API calls. Instead, defer these mutations to dedicated Nitro offline tasks (`server/tasks/`) triggered asynchronously via cron or manually out-of-band. Also, explicitly use the native Cloudflare environment KV binding (via `globalThis.KV` or `process.env.KV`) in tasks as the `unstorage` wrapper may obscure native types and parameters.
