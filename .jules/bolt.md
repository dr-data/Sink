## 2024-05-15 - Inline Database Migrations Cause Write Amplification
**Learning:** In Cloudflare KV, performing inline data migrations (e.g., updating a record and using `KV.put` during a `GET` request/list operation) to add metadata or change formats causes severe write amplification. Every read operation that encounters an un-migrated record triggers a write, which leads to high write costs (66k+ writes/month) and degrades read performance. Serverless environments like NuxtHub/Cloudflare shouldn't mix background migrations with real-time user-facing read queries.
**Action:** Remove inline `KV.put` from read operations like `server/api/link/search.get.ts`. Migrate the data offline or via dedicated Nitro tasks instead. When returning un-migrated data in a read query, simply format it correctly in memory before returning without persisting the changes inline.
